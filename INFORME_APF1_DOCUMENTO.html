1. Definición Inicial del Sistema

1.1. Nombre del Proyecto y Justificación

EcoTechTrack es una solución web empresarial orientada a la trazabilidad y fiscalización del ciclo de vida de los Residuos de Aparatos Eléctricos y Electrónicos (RAEE). En el Perú, conforme al D.S. N° 009-2019-MINAM, las entidades generadoras tienen la obligación legal y ambiental de garantizar que sus activos informáticos dados de baja sean entregados únicamente a Empresas Operadoras de Residuos Sólidos (EO-RS) autorizadas, evitando la contaminación por metales pesados (plomo, mercurio y cadmio) y asegurando su correcta valorización.

Justificación Técnica y de Negocio: Resuelve la dispersión de información en hojas de cálculo manuales, elimina el riesgo de pérdida o tráfico ilegal de componentes informáticos obsoletos, y automatiza la auditoría de cada residuo desde su baja hasta su disposición final.

1.2. Alcance del Sistema en esta Primera Fase

En esta fase inicial (APF1), se implementa la API RESTful del backend con: (1) Catálogo y registro de equipos en desuso, (2) Gestión de Almacenes de acopio temporal, (3) Registro de Empresas Gestoras formalmente autorizadas, y (4) Trazabilidad inmutable de cambios de estado mediante la entidad HistorialMovimiento.

1.3. Usuarios del Sistema (Roles Esperados)

Rol del Sistema Perfil / Actor Real Responsabilidades Principales
Administrador Ambiental Jefe de TI / Resp. Ambiental Declara la baja técnica de equipos, aprueba solicitudes de recojo y consulta métricas.
Encargado de Almacén Custodio de Depósito Registra el ingreso físico al almacén temporal, pesa el lote y hace entrega al transportista.
Operador Empresa Gestora Conductor / Técnico EO-RS Recepciona el residuo con guía de remisión, reporta traslado e informa la valorización/disposición.
Auditor / Fiscalizador OEFA / Auditor Interno Consulta la línea de tiempo inmutable, certifica actas de baja y verifica trazabilidad legal.

1.4. Diagrama de las Entidades Principales del Modelo de Dominio

[EMPRESA_GESTORA] (1) <======== (N) [RESIDUO_ELECTRONICO] (N) ========> (1) [ALMACEN]
                                              || (1)
                                              \\/ (N)
                                  [HISTORIAL_MOVIMIENTO]

Cardinalidad: Una Empresa Gestora atiende múltiples residuos (1:N); un Almacén custodia múltiples residuos (1:N); y cada Residuo Electrónico posee una colección cronológica de eventos de trazabilidad (1:N).

2.2. Arquitectura de Software en Capas Desacopladas

Se implementó el patrón arquitectónico en capas con Inyección de Dependencias por Constructor (buena práctica enseñada en la Sesión 2 para garantizar alta cohesión y bajo acoplamiento):

📂 Paquetes de la Arquitectura
  • controller/: Controladores REST (@RestController, códigos HTTP).
  • service/ & service/impl/: Lógica de negocio y transacciones (@Transactional).
  • repository/: Interfaces JPA Repository con consultas derivadas.
  • model/: Clases entidad (@Entity, @Table) y Enums.
  • dto/: Request/Response DTOs desacoplados de la persistencia.
  • exception/: Manejo global centralizado con @RestControllerAdvice.
  • config/: Semillero automático con CommandLineRunner.

3. Modelo de Dominio y Relaciones entre Entidades

3.1. Clases Java con Anotación @Entity y sus Atributos

El modelo de datos se diseñó cubriendo la totalidad de requerimientos del Tema 4 de la consigna oficial, implementando 4 entidades JPA estructuradas:

Entidad JPA Atributos Representativos Relaciones Implementadas
ResiduoElectronico
Entidad Principal		 id (PK), codigoIdentificacion (UK), descripcion, categoria (Enum), marca, modelo, numeroSerie, pesoKg, estado (Enum), observaciones, fechaRegistro, fechaActualizacion • @ManyToOne ➔ Almacen
• @ManyToOne ➔ EmpresaGestora
• @OneToMany ➔ HistorialMovimiento
EmpresaGestora
Operador RAEE		 id (PK), ruc (UK 11 dígitos), razonSocial, registroAutorizacion (MINAM), email, telefono, direccion • @OneToMany(mappedBy="empresaGestora") ➔ Colección de residuos asignados para recojo.
Almacen
Custodia Temporal		 id (PK), codigo (UK), nombre, sede, direccion, capacidadKg, responsable • @OneToMany(mappedBy="almacen") ➔ Colección de residuos en custodia temporal en el depósito.
HistorialMovimiento
Trazabilidad/Auditoría		 id (PK), estadoAnterior, estadoNuevo, fechaMovimiento, responsable, observaciones • @ManyToOne ➔ ResiduoElectronico (clave foránea residuo_id).

3.2. Fragmento de Código: Relaciones en ResiduoElectronico.java

@Entity @Table(name = "residuos_electronicos") public class ResiduoElectronico { @Id @GeneratedValue(strategy = GenerationType.IDENTITY) private Long id; @Column(name = "codigo_identificacion", nullable = false, unique = true, length = 50) private String codigoIdentificacion; // Relación Many-to-One con Almacén @ManyToOne(fetch = FetchType.LAZY) @JoinColumn(name = "almacen_id") private Almacen almacen; // Relación Many-to-One con Empresa Gestora RAEE @ManyToOne(fetch = FetchType.LAZY) @JoinColumn(name = "empresa_gestora_id") private EmpresaGestora empresaGestora; // Relación One-to-Many con el Historial de Auditoría @OneToMany(mappedBy = "residuo", cascade = CascadeType.ALL, orphanRemoval = true) @OrderBy("fechaMovimiento DESC") private List<HistorialMovimiento> historialMovimientos; }
